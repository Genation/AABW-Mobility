# MCP Server - Architecture

> **Spec:** MCP Protocol 2025-11-25 | **Transport:**
> WebStandardStreamableHTTPServerTransport

---

## 1. Process Model

Two independent processes, same codebase:

```
Terminal 1: deno task mcp  ->  http://localhost:8909/mcp   (MCP server, app.mcp.ts)
Terminal 2: deno task dev  ->  http://localhost:8907/api   (REST API, app.ts)
```

Both use Hono but are deployed independently. MCP server does **not** proxy to
REST API -- it calls health service directly.

---

## 2. Transport Layer

### WebStandardStreamableHTTPServerTransport

The MCP SDK provides `WebStandardStreamableHTTPServerTransport` which implements
the
[Streamable HTTP transport spec](https://modelcontextprotocol.io/specification/2025-11-25/basic/transports).

Key options:

```typescript
new WebStandardStreamableHTTPServerTransport({
  sessionIdGenerator: () => sessionId,   // fixed per session
  enableJsonResponse: true,              // use JSON instead of SSE for responses
  onsessioninitialized: (sid) => { ... } // callback when initialize completes
})
```

**Important:** Each transport is created once per session and **must not be
reused** after `close()`.

### Session-Per-Request Pattern

The server follows a strict session-per-request lifecycle:

```
Request arrives (POST /mcp)
   |
   |-- No mcp-session-id header -> CREATE new session
   |
   |-- Has mcp-session-id + found in registry -> REUSE existing session
   |
   --+ Has mcp-session-id + NOT found -> REJECT (HTTP 400)
```

The session ID is generated by the server (UUID v4), not the client. The
transport receives the session ID via `sessionIdGenerator`, and the server
returns it in the `mcp-session-id` response header. Clients must include this
header on subsequent requests.

## 3. Session Registry

The session registry is a `Map<string, SessionEntry>` that holds all active
sessions in memory.

```typescript
interface SessionEntry {
  transport: WebStandardStreamableHTTPServerTransport;
  server: McpServer;
  createdAt: number; // Date.now() when created
  lastActivity: number; // Date.now() of last request
  initialized: boolean; // true after initialize handshake completes
}
```

The registry lives in `app.mcp.ts` (production) as an inline variable. Test
setup (`setup-mcp.ts`) creates its own isolated registry.

Session lifecycle limits:

| Condition             | Threshold | Action                        |
| --------------------- | --------- | ----------------------------- |
| Uninitialized session | > 30s     | Sweeper evicts                |
| Idle session          | > 5 min   | Sweeper evicts                |
| Max sessions          | 100       | Evict oldest idle on overflow |

The sweeper runs every 60 seconds in the background without blocking request
handling.

## 4. Middleware Stack

The Hono app applies middlewares in this order (top-to-bottom):

```
CORS (cors middleware)
  -> requestIdMiddleware      (inject requestId)
  -> mcpRequestLogMiddleware  (log all requests)
  -> originValidationMiddleware (403 if origin disallowed)
  -> mcpAuthMiddleware        (401 if no/invalid token)
  -> MCP Handler (POST /mcp or GET /mcp)
```

### requestIdMiddleware

Injects a UUID `requestId` into the Hono context. All subsequent logging uses
this ID for correlation.

```typescript
c.set("requestId", crypto.randomUUID());
```

### mcpRequestLogMiddleware

Logs HTTP method, path, user-agent on entry. Logs method, path, status on exit.

### originValidationMiddleware

Per MCP spec DNS rebinding protection. If `ALLOWED_ORIGINS[0] !== "*"` and the
request's `Origin` header is not in the allowed list, returns HTTP 403.

### mcpAuthMiddleware

Applies only to `/mcp` routes. Extracts `Authorization: Bearer <token>`, calls
`verifySupabaseJwt()`. If token is missing or role is `"anon"`, returns
HTTP 401.

Public endpoints (`/health`, `/ready`) are not affected by auth.

## 5. Server Factory

The `createMcpServer()` function in `mcp-hono.ts` creates a new `McpServer`
instance and registers all tools and resources:

```typescript
import { registerHealthTools } from "./modules/health/health.mcp.tool.ts";
import { registerHealthResources } from "./modules/health/health.mcp.resource.ts";

function createMcpServer(): McpServer {
  const server = new McpServer(
    { name: "geo-tools-mcp-server", version: "1.0.0" },
    {
      capabilities: {
        tools: {}, // enables tools/list, tools/call
        resources: {}, // enables resources/list, resources/read
        logging: {}, // enables logging/message
      },
      instructions: "This MCP server provides health data management tools...",
    },
  );
  registerHealthTools(server);
  registerHealthResources(server);
  return server;
}
```

**Important:** `capabilities: { resources: {} }` must be declared to enable
resource-related methods. Without it, `resources/list` returns "Method not
found".

## 6. Error Response Architecture

Errors are classified by the layer they originate from:

### HTTP Layer Errors (non-200)

- Returned **before** the transport handles the request
- Includes auth failure (401), origin rejection (403), protocol version (400),
  malformed JSON-RPC
- Response is a raw JSON object, not a `CallToolResult`

### JSON-RPC Layer Errors (HTTP 200/202)

- Returned **by** the transport after processing
- Include validation errors, not-found errors, internal errors
- Response is a `CallToolResult` with `isError: true` in the body

```typescript
// HTTP layer error (auth missing)
HTTP 401
{
  "jsonrpc": "2.0",
  "error": { "code": -32001, "message": "Unauthorized" }
}

// JSON-RPC tool error (record not found)
HTTP 200/202
{
  "jsonrpc": "2.0",
  "id": 2,
  "result": {
    "content": [{ "type": "text", "text": "{\"error\":\"Not found\",\"code\":-32601}" }],
    "isError": true
  }
}
```

## 7. Response Header Propagation

The MCP transport may set `mcp-session-id` and `mcp-protocol-version` headers on
the response. These must be manually propagated because Hono's response wrapping
can lose them:

```typescript
const response = await entry.transport.handleRequest(c.req.raw);
const cloned = new Response(response.body, response);
for (const [key, value] of response.headers) {
  if (
    key === "mcp-session-id" ||
    key === "mcp-protocol-version" ||
    key === "x-request-id"
  ) {
    cloned.headers.set(key, value);
  }
}
return cloned;
```

## 8. Production vs. Test Architecture

| Aspect             | Production (`app.mcp.ts`)                        | Test (`setup-mcp.ts`)                         |
| ------------------ | ---------------------------------------------- | --------------------------------------------- |
| Session registry   | Inline `new Map()`                             | Imported from `mcp-hono.ts`                   |
| Server creation    | Via `getOrCreateSession()` from `mcp-hono.ts`  | Via `getOrCreateSession()` from `mcp-hono.ts` |
| Transport creation | Via `getOrCreateSession()` from `mcp-hono.ts`  | Via `getOrCreateSession()` from `mcp-hono.ts` |
| Middlewares        | All 4 middlewares                             | Auth only + CORS                              |
| CORS               | Environment-based `ALLOWED_ORIGINS`            | `origin: "*"`                                 |
| Port               | `MCP_PORT` env var (default 8909)              | Random high port (3100 + random)               |

Both use the same `McpServer` class, same
`WebStandardStreamableHTTPServerTransport`, same `registerHealthTools` /
`registerHealthResources` functions imported from the respective `.mcp.tool.ts`
and `.mcp.resource.ts` files.
