1
Normalize & coordinate check
core/text.py · normalize(), tokenize(), parse_coordinates()

NFC-normalize, lowercase, strip stray punctuation, then tokenize. A regex checks first whether the whole string is a lat/lng pair (unambiguous → short-circuits everything else).

input
raw = "bv bach mai"
output
tokens  = ["bv", "bach", "mai"]
coords  = None   # not "lat,lng"
2
Type-aware abbreviation expansion
core/understand.py · _apply_abbrev()

Looks up 3/2/1-gram windows in the abbreviation dictionary. The dictionary's type column decides behaviour: place types (category/brand/district/city/street/poi) are substituted into the text; intent/nearby types only set a hint flag so they don't corrupt the visible query.

input
tokens = ["bv", "bach", "mai"]
kb.abbrev["bv"] = {expansion: "Bệnh viện", type: "category"}
output
exp_tokens  = ["Bệnh", "viện", "bach", "mai"]
abbrev_hits = {"bv": "Bệnh viện"}
abbr_ent    = {"category": "Bệnh viện"}
3
Span linking (accent restore + typo fix + entity grounding)
core/understand.py · _link_spans() → data/kb.py phrase lexicon

Folds every token (strip accents + lowercase) and tries the longest n-gram (up to 6 tokens) against an accent-insensitive phrase lexicon of every POI/brand/street/district/city/category name, with exact match first, fuzzy (rapidfuzz) as backup. The first, longest, highest-priority match wins — poi > alias > street/brand > district/city > ward > category.

input
folded tokens = ["benh","vien","bach","mai"]
lexicon.exact("benh vien bach mai")
output
spans = [
  Span(start=0, end=4, type="poi",
       canonical="Bệnh viện Bạch Mai",
       payload="poi_id:...")
]
All 4 tokens are consumed by one span — the query collapses onto a single known POI, accents restored and typo-tolerant, in one lookup.
4
Category / attribute / brand / city / district detection
core/understand.py · _detect_category(), _detect_attributes(), _detect_city()

Runs regex term-lookups against the parts of the query not already covered by a place span (so "hospital" words in a POI name don't get re-detected as a separate category). Here the whole query is already covered by the POI span, so category falls back to the abbreviation-derived one.

input
spans (from step 3), abbr_ent = {"category": "Bệnh viện"}
cat_text = ""   # fully covered by the POI span
output
category   = "Bệnh viện"
attributes = []
brand = district = city = None
5
Reference / nearby / navigation / ambiguity detection
core/understand.py · proximity-preposition, nav-marker, ambiguous-brand regexes

Checks for "gần / near / cạnh…" (nearby + a reference place), navigation markers ("chỉ đường", "directions"), current-location phrases ("gần đây"), and short bare brand names that map to >1 POI (ambiguous, e.g. "galaxy").

input
qfold = "benh vien bach mai"
output
has_nav = has_current_loc = False
reference_poi = reference_area = None
ambiguous = None

None of these fire for this query — it is a plain, unambiguous named-place lookup.

6
Intent classification
core/understand.py · priority if/elif chain over 9 intents

Deterministic priority rules: Coordinate > Navigation > Ambiguous > Nearby > Address > POI > Brand-Category > Discovery > Category. A resolved poi_span with no competing "reference forces category" condition wins outright.

input
poi_span present, ref_forces_category = False
has_nav / ambiguous / has_current_loc = False
output
intent = "POI Search"
7
Reconstruct normalized query + confidence
core/understand.py · _build_normalized(), _confidence()

For a POI-Search intent the canonical POI name is used directly (correct casing/accents), instead of rebuilding token-by-token. Confidence starts at a base and adds evidence-based bonuses.

input
intent="POI Search", ent={poi_name, category}
spans=[poi], abbrev_hits={"bv": "Bệnh viện"}
output
normalized_query = "Bệnh viện Bạch Mai"
confidence = 0.82
confidence = 0.55 base + 0.06 × 2 entities = 0.67 + 0.10 (a "poi" span exists) = 0.77 + 0.05 (an abbreviation was resolved) = 0.82

3
Hybrid retrieval — dense embeddings + BM25, min-max fused
index/store.py · HybridIndex.retrieve() · index/embed.py

Two independent retrievers score every POI document: a local multilingual-e5-small sentence embedder (E5-style "query: " / "passage: " prefixes, cosine similarity) for meaning, and BM25 over accent-folded tokens for exact lexical overlap. Both score arrays are min-max normalized to [0,1] then combined 0.65 · vector + 0.35 · lexical.

query: "quán cà phê yên tĩnh để làm việc"

Files behind each step

tascomaps/core/text.py — Vietnamese normalize/fold/tokenize/coordinate primitives (P6 step 1)
tascomaps/core/understand.py — full P6 engine: abbreviation, span linking, intent, reconstruction, confidence (P6 steps 2–7; also P7 step 1)
tascomaps/data/kb.py, data/loader.py — unified knowledge base + accent-insensitive phrase lexicon
tascomaps/index/store.py — POI document construction + hybrid (dense+BM25) retrieval (P7 steps 2–3)
tascomaps/index/embed.py — multilingual-e5-small embedder with TF-IDF fallback
tascomaps/engines/semantic_search.py — multi-signal reranking + explanations (P7 steps 4–5)
eval/evaluate.py — gold-set scoring producing the metrics shown at the top

Data is synthetic hackathon data (Tasco Maps AI Challenge); numbers on this page were generated by directly invoking understand() and SemanticSearchEngine.search() in this repo, not hand-written.
